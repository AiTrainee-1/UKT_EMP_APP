PAGE: Attendance (tab 2 of 5)
--------------------------------------------------------------------
Route:    /(tabs)/attendance
File:     app/(tabs)/attendance.tsx
Purpose:  Monthly attendance overview, calendar, trend chart.

COMPENSATION ON THE CALENDAR (staff; additive, an older backend sends none):
  Every attendance day can carry compensationKind / compensationMinutes /
  compensationNote (GET /attendance/employee/{id} records, and
  /attendance/employee-shift-stats dailyLogs). A day that used a compensation is
  drawn SOLID in that kind's own colour with its own white symbol (every ordinary
  status is a soft tint), so it can never be mistaken for one:
    ot_allowance       lime     clock-plus-outline     Late-in allowance used
    window_late_in     sky      clock-start            Company late-in time
    window_early_out   fuchsia  clock-end              Company early-out time
    relaxation         emerald  sofa-outline           Compensation day (relaxation)
    birthday           rose     cake-variant-outline   Birthday leave (paid)
  Late-In / Early-Out rings still go on top. The colours live in
  src/lib/attendanceVisual.ts (COMPENSATION_TONES, pure + tested). A kind the app
  does not know is NOT recoloured: the day keeps its status colour and the day
  sheet shows a plain "Compensation" chip and the server's own sentence.
  - Legend: a "COMPENSATION DAYS" section lists the five kinds, once the
    employee's profile has said "staff" (never for a production employee, and
    not while the profile is still loading).
  - Day sheet: a chip for the kind (an allowance says how many minutes the arrival
    used), the server's compensationNote as a quote line, and a "See all my
    compensation" link -> /compensation. A birthday / relaxation day (made up by
    the compensation, no punches) shows the compensation as its badge and a
    "Day counted as" row (Present / Half Day), and offers no Missing Punch /
    Apply Leave remedy.
  - Monthly Overview: chips such as "2 late-in allowance" for the month.

UI:
  - Gradient header with hamburger + month pager (prev/next; next
    disabled at current month)
  - GeoPunchCard: compact status banner -> /geo-punch or /on-duty
  - Sync-pending warning banner (conditional)
  - "Assigned Shift" banner -> /shift
  - 3x2 summary grid: Working Days / Present / Absent / Late /
    Half Shift / Leave
  - "Monthly Trend" card with AttendanceTrendChart (hand-drawn SVG bar chart)
  - Casual Leave eligibility card: eligible/not-eligible badge, yearly
    entitlement / used / remaining stats
  - AttendanceCalendar grid card: tap a day -> detail BottomSheet
    (status, first/last punch, punch count, quick-action chips for
    Absent/Half Shift/Late days)
  - Color legend row
  - SideDrawer

Actions:
  - Pull-to-refresh
  - Page months
  - Tap shift banner -> /shift
  - Tap calendar day -> detail sheet with contextual actions
    (Apply Leave -> /(tabs)/leave, Missing Punch -> /missing-punch,
    Permission -> /requests)
  - Open drawer

API calls:
  - useAttendance(employeeId, month, year) -> GET /attendance/employee/{id}
  - useShift(employeeId) -> GET /shift-assignments
  - useAttendanceSyncStatus() -> GET /attendance/sync-status
  - useCLEligibility(employeeId) -> GET /casual-leaves/my-eligibility
  - (via GeoPunchCard) useGeoPunchStatus() -> GET /attendance/geo-punch/status

Conditional content:
  - Sync warning only if pendingSync
  - Shift banner only if a shift is assigned
  - CL card only if eligibility data present

PAGE: Approvals (tab 4 of 5 — MANAGER ONLY)
--------------------------------------------------------------------
Route:    /(tabs)/approvals
File:     app/(tabs)/approvals.tsx
Purpose:  Managers review and approve/reject team requests across
          8 categories.

UI:
  - Gradient header ("Approvals / Review pending requests")
  - Horizontal scroll of per-category stat cards: Leave, Permission,
    Casual Leave*, Attendance*, Missing Punch*, Outpass*, Compensation*,
    Resignations*
    (starred categories only appear if the manager has that specific
    approval capability) — each shows a pending count, tap to switch tab
  - "Compensation" = Holiday / Sunday work claims HR raised for the team:
    employee, work date + shifts, Sunday / holiday, reason, who raised it,
    approval progress. The sheet says "Approving adds 0.50 shift to <name>'s
    compensation balance; rejecting is final". The approval is final (the HOD
    is the only step) and the toast names what was added to whom.
  - FlatList of request cards for the active category: avatar initial,
    employee name/code, type chip, date, reason preview, inline
    Approve/Reject buttons, staggered entrance animation
  - Empty state: "All caught up!"
  - Detail BottomSheet (generic — leave/permission/casualLeave/
    attendance/missingPunch/outpass): full fields + optional comment
    TextInput + Approve/Reject buttons
  - Separate detail BottomSheet for resignation: reason, last working
    date, submitted date, survey Q&A, comment, Approve/Reject
  - Toast

Actions:
  - Switch category tab
  - Tap a card or its inline buttons to open the detail sheet
  - Approve/reject with an optional comment
  - Pull-to-refresh

API calls:
  - useManagerProfile(!!user) -> GET /manager/me
  - usePendingRequests() -> GET /manager/pending-requests
  - useApproveLeave() -> PATCH /manager/leave-requests/{id}/status
  - useApprovePermission() -> PATCH /manager/permissions/{id}/status
  - useResignationAction() -> PATCH /manager/resignations/{id}/action
  - useApproveCasualLeave() -> PATCH /manager/casual-leaves/{id}/status
  - useApproveAttendance() -> PATCH /manager/attendance-requests/{id}/status
  - useApproveMissingPunch() -> PATCH /manager/missing-punch-requests/{id}/status
  - useApproveOutpass() -> PATCH /manager/outpass-requests/{id}/status
  - useApproveHolidayWork() -> PATCH /manager/holiday-work/{id}/status
    body {status, comment}; GET /manager/pending-requests carries
    holidayWorkClaims, GET /manager/me carries canApproveCompensation and
    pendingCompensationCount (already inside pendingApprovalsCount). Errors
    such as APPROVE_COMPENSATION_DISABLED or "already approved" are shown as
    the server's own sentence; a refusal refreshes the list and the profile.

Conditional/role-gated:
  - The whole tab is hidden from non-managers (href: isManager ?
    undefined : null in the tab layout)
  - Within the screen, Casual Leave / Attendance / Missing Punch /
    Outpass / Compensation / Resignation tabs each only appear if the
    matching manager.canApprove* flag is true (Outpass reuses
    canApprovePermissions; Compensation = canApproveCompensation, absent on
    an older backend = hidden)
  - If the open tab disappears (HR switched the head's approval switch off and
    the profile refetch no longer lists it), the screen falls back to the
    Leave tab instead of an unselected, empty list
  - The tab-bar badge is the sum of the pending counts of the tabs this screen
    shows, every count read from /manager/me: leave + permission, plus casual
    leave / attendance / missing punch / compensation / resignation when that
    tab is listed (src/lib/approvalBadge.ts, which the screen also uses to
    decide the tab list). It is NOT the server's pendingApprovalsCount: that
    total also counts On-Duty requests, and this app has no On-Duty tab, so the
    badge could never be cleared. The Outpass tab is counted from the
    additive pendingOutpassCount key of /manager/me (an older backend without
    it leaves outpass out of the badge). Only an older backend that sends no
    per-kind count falls back to pendingApprovalsCount

PAGE: Profile (tab 5 of 5)
--------------------------------------------------------------------
Route:    /(tabs)/profile
File:     app/(tabs)/profile.tsx
Purpose:  Employee's own profile, HR-record viewer, password change,
          resignation entry point.

UI:
  - Parallax hero card (gradient, hamburger, tappable Avatar with a
    camera-edit badge) — shrinks on scroll
      * Top row: Active Duty / On Leave / etc. status pill (derived
        from emp.status via statusLabel()) + "ROLL #{employeeCode}"

      * Tag row (each shown only if the underlying value exists):

  - Digital ID Pass quick-link card: icon, title + static "NFC
    ACTIVE" badge (cosmetic label describing the physical card's

    arrow -> /idcard
  - 3-stat row: Work Contact (phone) / Join Date / Workstation
  - Personal Details ExpandableCard (open by default):
      * Legal Full Name + Gender • Blood Group (2-up)
      * Date of Birth (with computed age) + Nationality (2-up)
      * Official Corporate Email, with a "Verified" badge when present
      * Emergency ICE Contact, with a tap-to-call button when a phone
        number can be parsed out of the free-text field
  - Family & Dependents ExpandableCard: badge shows "N Members";
    body lists each dependent (name, relation) with "Nominee" /
    "Health" mini-badges when applicable, or an empty-state line
  - Employment & Hierarchy ExpandableCard: badge shows "Confirmed"
    (green) or "On Probation" (yellow) from emp.isConfirmed; body
    shows Division (department), Shift Rules (from useShift), and
    Supervisor (emp.reportingManager, or "Not assigned")
  - Bank & Compliance ExpandableCard (lock icon in the header): Bank
    Name / IFSC (2-up), masked Account Number, PF / ESI Numbers
    (2-up), UAN Number
  - "SECURITY & ACCOUNT" section label + actions card:
      * "Change Portal Password" row, subtitle = time since
        emp.passwordUpdatedAt (e.g. "Last updated 42 days ago") ->
        opens the Change Password BottomSheet
      * "Resignation & Exit" row, subtitle reflects live resignation
        status -> new submission goes to /resignation/warning;
        an in-progress/approved one shows an Alert with the detail
        (rejected re-opens the warning screen to resubmit)
  - Full-width "Sign Out of UKTextiles" pill button (red)
  - Footer: "UKTextiles Enterprise Mobile Platform" + app version
  - SideDrawer
  - Change Password BottomSheet: Employee Code (read-only), New
    Password, Confirm Password
  - Toast

Actions:
  - Tap avatar -> pick / replace / remove a device-local profile
    photo (NOTE: this photo is never sent to the server — see
    Section 5, useLocalProfilePhoto)
  - Expand/collapse each accordion card independently
  - Tap the Emergency Contact call button -> dials the parsed number
  - Change password
  - Navigate to /resignation/warning (new submission or resubmit),
    or view an Alert with the current resignation status
  - Sign out (confirm Alert)
  - Open drawer

API calls:
  - useEmployee(employeeId) -> GET /employees/{id} (now also returns
    name, nationality, workstation, zone, staffTier, hasPassword,
    passwordUpdatedAt, reportingManager, isConfirmed/confirmationDate)
  - useShift(employeeId) -> GET /shift-assignments
  - useFamily(employeeId) -> GET /my/family
  - useMyResignation(employeeId) -> GET /my/resignation
  - useLocalProfilePhoto(employeeId) — AsyncStorage only, no API call
  - setPasswordRequest() -> POST /auth/set-password (also stamps
    Employee.password_updated_at on the backend)

Conditional content:
  - Header tag chips (Staff Tier / Shift / Zone) each render only if
    that field is populated for the employee
  - Family & Dependents shows an empty-state line instead of a list
    when the employee has no FamilyDependent rows
  - The Employment & Hierarchy "Confirmed"/"On Probation" badge and
    the Resignation & Exit subtitle are both derived, not raw fields
  - NFC ACTIVE is a static label, not a live capability — there is no
    NFC integration anywhere in this codebase

  DockTabIcon
    macOS-dock-style magnifying/lifting tab icon with a tinted well
    and a running-dot indicator.
    Used by: bottom tab bar.

  DocumentCategoryCard
    Grouped-by-category document list card with view (in-app image
    preview or share sheet) / download actions.
    Used by: Documents screen.

  GeoPunchCard
    Compact status banner summarizing today's Office Geo Punch /
    On-Duty state; links to /geo-punch or /on-duty.
    Used by: Attendance tab.

  GlassTabBar
    A fully-built custom floating translucent-pill tab bar with
    spring-animated items and badges. NOTE: this component exists in
    the codebase but is currently UNUSED — the tab layout uses the
    built-in Expo Router tab bar instead.

  HamburgerToggle
    Animated SVG hamburger<->X icon (line-morph).
    Used by: Home, Attendance, Leave, Notifications, Profile headers.

  KeyboardAvoider + useKeyboardVisible
    iOS keyboard-avoiding wrapper (Android relies on native resize);
    hook reports keyboard visibility.
    Used by: Login, Set Password, Chat, Resignation Survey, BottomSheet.

  LeaveCard
    Leave-request list card: type icon, status badge, date range/
    half-day label, day-count badge, reason; stagger-in animation.
    Used by: Leave tab.

  LiveFeedTicker
    Auto-scrolling marquee of recent check-in/out events.
    Used by: Home screen.

  PermissionGate
    Full-screen blocking overlay requesting Location/Camera (+
    silent Notification) permission on first launch and on every
    foreground; offers retry or "Open Settings".
    Mounted globally in the root layout (app-wide).

  Reveal
    Staggered fade+slide entrance wrapper (Moti-based), respects OS
    Reduce Motion setting.
    Used by: Home (quick action tiles), and generally any list.

  SalarySlipCard
    Salary-slip list row (month/year, net pay, Emailed/Generated badge).
    Used by: Salary Slips list.

  SideDrawer
    Full hamburger navigation drawer — see Section 4 for its full
    contents.
    Used by: Home, Attendance, Leave, Notifications, Profile.

  SlideToPunch
    Slide-to-unlock-style gesture control that punches attendance
    (or hands off to On-Duty) with live location capture.
    Used by: Home screen, pinned above the tab bar.

  UKTLogo
    Company logo as an inline SVG (traced artwork), size-configurable.
    Used by: Splash, Login, Company, SideDrawer, ID Card.

  support/ContactBlockCard
    HR's contact details as tappable Call / WhatsApp / Email rows, for a screen
    whose own reply already carries the HR block (askHr.contact, hrContact).
    Uses the same helpers as SupportContactCard (contactActions,
    openContactAction); falls back to the HR contact saved on the phone, then
    to a plain sentence with no numbers.
    Used by: Compensation (Ask tab), HOD Assignment.

  outpass/OutpassFlipCard
    Two-sided animated flip card for an outpass request. Front =
    trip/employee details + QR code; back = approval trail. Card
    height auto-sizes to whichever face's content is taller.
    Used by: Outpass screen (active pass banner + preview sheet).

====================================================================
NOTES FOR PARITY / UI-RECREATION WORK
====================================================================

- Role gating is centered on three things:
    1. manager.isManager (Approvals tab + its per-category
       canApprove* capability flags)
    2. employee.employmentType === 'production' (drawer's Leave/
       Permissions items hidden for production staff; ID card & My
       Shift layouts differ; weekly schedule differs; the Compensation
       tile / drawer entry / calendar-legend section appear only once the
       profile has said 'staff')
    3. resignation.status (Profile screen's action-card state machine)

- Device-local-only data: the profile photo (useLocalProfilePhoto)
  is intentionally never sent to the server on mobile — it overrides
  the HR-uploaded photo only on that specific device. (The Employee
  Web App's equivalent DOES upload to the server — worth deciding
  whether these should match.)

- Polling intervals worth replicating exactly for a faithful
  recreation:
    Notifications                60 seconds
    Chat messages                4 seconds
    Outpass requests             30 seconds
    Geo-punch status             30 seconds
    On-duty session status       15 seconds
    Manager profile / pending    30 seconds
    Live feed                    20 seconds
    Mobile home summary          60 seconds

- GlassTabBar exists fully built in the codebase but is NOT wired
  into the tab layout — it's currently dead code, kept for possible
  future use.

- The root layout (app/_layout.tsx) also hosts several app-wide
  singletons with no dedicated screen of their own:
    ResignationGuard        polls /my/resignation, force-logs-out to
                             /resignation/deactivated on approval
    PushTokenRegistrar       registers the device's push token on login
    LiveLocationTracker      auto-resumes background-safe foreground
                             location pings
    NotificationTapHandler   routes a tapped push notification to
                             /(tabs)/notifications
    PermissionGate           blocking Location/Camera onboarding overlay
