====================================================================
Repo: D:\Projects\UK-textile-Mobi\uktextiles-employee-app
Stack: Expo Router (React Native), SDK 57
Purpose of this document: a complete, page-by-page inventory of every
screen, component, feature, and API call in the mobile app, for use as
a source-of-truth reference when recreating the UI (e.g. in Google
Stitch) with identical features and functionality.

  3. Reusable shared components
  4. Navigation structure (tab bar, side drawer, home quick actions)
  5. Full hook / API endpoint map

PAGE: Splash
--------------------------------------------------------------------
Route:    /
File:     app/index.tsx
Purpose:  Branded splash shown while auth state resolves, then redirects.

UI:
  - Gradient background
  - Animated UKTLogo with a pulsing ring behind it
  - "UKTextiles / Employee Portal" wordmark
  - 3 pulsing dots loader

    once useAuth().isLoading resolves.

    checkAuth() -> GET /auth/me (called from the root layout).

PAGE: Home (tab 1 of 5)
--------------------------------------------------------------------
Route:    /(tabs)/home
File:     app/(tabs)/home.tsx
Purpose:  Main dashboard — punch status, quick actions, attendance snapshot.

UI:
  - Header: hamburger (opens SideDrawer), greeting + live clock/date,
    bell icon with unread-count badge -> /(tabs)/notifications
  - "This Month's Overview" gradient banner: 4 stats (Working Days,
    Present, Absent, Leave), skeleton while loading
  - "Quick Actions" section: grid of tiles, first 6 shown by default,
    "Show all N / Show less" toggle expands to the full list
    (full 19-item list in Section 4 below)
  - "My Punches Today" card: chips of today's IN/OUT punches with
    times, or empty state
  - "Live Attendance" section: LiveFeedTicker — scrolling ticker of
    recent check-in/out events
  - "Company Location" card (conditional): tap opens native Maps app
    to the branch coordinates
  - "Digital ID Card" mini card (conditional): mini avatar/name/code/
    designation, QR icon -> /idcard
  - "Recent Attendance" row (conditional): 7 AttendanceDot chips
    (date + status icon)
  - "Upcoming Holidays" list (conditional, up to 3): date box + name +
    weekday + flag badge
  - Skeleton cards while loading
  - SlideToPunch bar pinned above the tab bar (slide-to-punch gesture)
  - SideDrawer (hamburger menu)

Actions:
  - Pull-to-refresh
  - Navigate to any Quick Action route
  - Tap bell -> notifications
  - Tap location card -> open native maps
  - Tap ID card mini -> /idcard
  - Slide-to-punch -> punch attendance, or hand off to On-Duty
  - Open side drawer -> logout confirm (Alert)

API calls:
  - useDashboard(employeeId) -> GET /dashboard/employee-summary
    (falls back to composing useLeaveBalances -> GET /leave-balances,
    useLeaveRequests -> GET /leave-requests,
    usePermissions -> GET /permissions)
  - useAppNotifications(employeeId) -> GET /notifications?employeeId=
  - useLiveFeed() -> GET /attendance/live-feed
  - useIdCard(employeeId) -> GET /idcard
  - useEmployee(employeeId) -> GET /employees/{id}
  - useAttendance(employeeId, month, year) -> GET /attendance/employee/{id}
  - (via SlideToPunch) useGeoPunchStatus() -> GET /attendance/geo-punch/status;
    useGeoPunch() -> POST /attendance/geo-punch
  - (via SideDrawer) useGeoPunchStatus(), useEmployee()

Conditional content:
  - Company Location card only if emp.branchLat/branchLng set
  - Digital ID card mini only if idCard or emp data present
  - Recent Attendance / Upcoming Holidays only if dashboard data present

PAGE: Approvals (tab 4 of 5 — MANAGER ONLY)
--------------------------------------------------------------------
Route:    /(tabs)/approvals
File:     app/(tabs)/approvals.tsx
Purpose:  Managers review and approve/reject team requests across
          7 categories.

UI:
  - Gradient header ("Approvals / Review pending requests")
  - Horizontal scroll of per-category stat cards: Leave, Permission,
    Casual Leave*, Attendance*, Missing Punch*, Outpass*, Resignations*
    (starred categories only appear if the manager has that specific
    approval capability) — each shows a pending count, tap to switch tab
  - FlatList of request cards for the active category: avatar initial,
    employee name/code, type chip, date, reason preview, inline
    Approve/Reject buttons, staggered entrance animation
  - Empty state: "All caught up!"
  - Detail BottomSheet (generic — leave/permission/casualLeave/
    attendance/missingPunch/outpass): full fields + optional comment
    TextInput + Approve/Reject buttons
  - Separate detail BottomSheet for resignation: reason, last working
    date, submitted date, survey Q&A, comment, Approve/Reject
  - Toast

Actions:
  - Switch category tab
  - Tap a card or its inline buttons to open the detail sheet
  - Approve/reject with an optional comment
  - Pull-to-refresh

API calls:
  - useManagerProfile(!!user) -> GET /manager/me
  - usePendingRequests() -> GET /manager/pending-requests
  - useApproveLeave() -> PATCH /manager/leave-requests/{id}/status
  - useApprovePermission() -> PATCH /manager/permissions/{id}/status
  - useResignationAction() -> PATCH /manager/resignations/{id}/action
  - useApproveCasualLeave() -> PATCH /manager/casual-leaves/{id}/status
  - useApproveAttendance() -> PATCH /manager/attendance-requests/{id}/status
  - useApproveMissingPunch() -> PATCH /manager/missing-punch-requests/{id}/status
  - useApproveOutpass() -> PATCH /manager/outpass-requests/{id}/status

Conditional/role-gated:
  - The whole tab is hidden from non-managers (href: isManager ?
    undefined : null in the tab layout)
  - Within the screen, Casual Leave / Attendance / Missing Punch /
    Outpass / Resignation tabs each only appear if the matching
    manager.canApprove* flag is true (Outpass reuses canApprovePermissions)

    verified/not-verified card with employee identity details

PAGE: On-Duty
--------------------------------------------------------------------
Route:    /on-duty
File:     app/on-duty/index.tsx
Purpose:  Off-site work session — request a destination, then
          capture selfie+GPS punches for up to 4 slots over the day.

UI (branches entirely on session state):
  - No session / new request: destination TextArea, "Submit for
    Approval" button
  - Pending (HOD or HR): status banner, destination (read-only),
    HOD-approved note if applicable, "Refresh Status" button
  - Active:
      * status banner (+ provisional note if still pending approval
        upstream)
      * destination/start-time cells
      * punch-review card (photo preview, punch#/time, Retake/
        Submit/Cancel) shown mid-capture
      * "All 4 punches in" done banner
      * "Today's Punches" list — 4 slots, tap an open slot to
        capture via camera + GPS
      * "Mark On-Duty as Done" button
  - Completed / Rejected: done card with icon, destination,
    completion/rejection reason, "Submit New On-Duty Request" +
    "Back to Attendance" buttons
  - Toast throughout

Actions:
  - Submit a destination request
  - Capture a punch (camera photo + GPS) per open slot

NOTES FOR PARITY / UI-RECREATION WORK
====================================================================

- Role gating is centered on three things:
    1. manager.isManager (Approvals tab + its per-category
       canApprove* capability flags)
    2. employee.employmentType === 'production' (drawer's Leave/
       Permissions items hidden for production staff; ID card & My
       Shift layouts differ; weekly schedule differs)
    3. resignation.status (Profile screen's action-card state machine)

- Device-local-only data: the profile photo (useLocalProfilePhoto)
  is intentionally never sent to the server on mobile — it overrides
  the HR-uploaded photo only on that specific device. (The Employee
  Web App's equivalent DOES upload to the server — worth deciding
  whether these should match.)

- Polling intervals worth replicating exactly for a faithful
  recreation:
    Notifications                60 seconds
    Chat messages                4 seconds
    Outpass requests             30 seconds
    Geo-punch status             30 seconds
    On-duty session status       15 seconds
    Manager profile / pending    30 seconds
    Live feed                    20 seconds
    Mobile home summary          60 seconds

- GlassTabBar exists fully built in the codebase but is NOT wired
  into the tab layout — it's currently dead code, kept for possible
  future use.

- The root layout (app/_layout.tsx) also hosts several app-wide
  singletons with no dedicated screen of their own:
    ResignationGuard        polls /my/resignation, force-logs-out to
                             /resignation/deactivated on approval
    PushTokenRegistrar       registers the device's push token on login
    LiveLocationTracker      auto-resumes background-safe foreground
                             location pings
    NotificationTapHandler   routes a tapped push notification to
                             /(tabs)/notifications
    PermissionGate           blocking Location/Camera onboarding overlay
